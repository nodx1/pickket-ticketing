# 외부 연동 대상·규격 확정서 (초안)

> 과업지시서 3-4) "연동 대상 업체·장비, 연동 수량, 인터페이스 및 테스트 범위는 해당 연동 개발 착수 전에 발주사와 수행사가 서면으로 확정한다."
> 이 문서는 구현된 인터페이스를 기준으로 한 **확정용 초안**이다. 빈칸(＿＿)을 협의해 채운 뒤 서명한다.

## 2. 현장 단말 인터페이스

### 2-1. 공통

- 기본 주소: `https://api.pickket.kr` (스테이징 ＿＿)
- 인증: 단말 키(`pkt_term_…`). 주최사 대시보드 「현장 입장 관리 → 단말 등록」에서 발급, **발급 화면에서 한 번만 보인다.** 분실 시 폐기 후 재발급.
- 단말은 등록 시 지정한 **이벤트·게이트에 고정**되고, 허용 등급(입장 권한)을 둘 수 있다.
- 시각: ISO 8601(UTC 오프셋 포함). 미래 시각은 서버 시각으로 대체.

### 2-2. REST

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `POST /api/v1/terminals/scan` | 헤더 `X-Terminal-Key`, 본문 `{"payload": "PKT:…" 또는 티켓번호, "manual": false, "scanned_at": "…"}` | 판정 객체(2-4) |
| `POST /api/v1/terminals/heartbeat` | 헤더 `X-Terminal-Key` | `{"ok": true}` |
| `GET /api/v1/terminals/blocklist` | 헤더 `X-Terminal-Key` | `{"version", "blocked":[{"ticket_no","reason"}], "sanctioned":[티켓번호…]}` |
| `GET /api/v1/terminals/me` | 헤더 `X-Terminal-Key` | 단말 정보(이벤트·게이트·허용 등급) |

키가 틀리거나 일시중지·폐기된 단말은 `401`.

### 2-3. Socket.IO (권장)

- 주소 `wss://api.pickket.kr/ws/socket.io/`, 네임스페이스 `/terminal`, `transports: ["websocket"]`, `auth: {"key": "pkt_term_…"}`
- 서버 → 단말

| 이벤트 | 시점 | 데이터 |
|---|---|---|
| `hello` | 접속 직후 | 단말 id·이벤트·게이트·이름·종류 |
| `blocklist.sync` | 접속 직후, 차단·제재 변경 커밋 후 | 2-2 차단 목록과 같음 |
| `fraud.alert` | 같은 이벤트 어느 단말에서든 부정 탐지 시 | 판정 객체 + `terminal_name` |
| `ticket.admitted` | 다른 단말 입장 시 | `{ticket_no, gate, at}` — 오프라인 대비 캐시용 |
| `permission.update` | 이 단말의 게이트·허용 등급·상태 변경 | `{gate, allowed_tier_ids, status}` |

- 단말 → 서버: `scan`(ack 로 판정 객체), `heartbeat`(20초 권장)

### 2-4. 판정 객체

```json
{
  "result": "admitted | reentry_ok | rejected",
  "code": "admitted | reentry_ok | invalid_qr | forged_qr | expired_qr | not_found | wrong_event |
           blocked_ticket | sanctioned_account | gate_not_allowed | qr_replay | duplicate_ticket |
           cancelled | not_admission_day | manual_not_allowed",
  "message": "관객에게 보여 줄 한국어 문구",
  "ticket_no": "TKT-…", "holder": "관**호", "tier": "VIP", "gate": "정문",
  "terminal_id": "…", "attended_date": "2026-11-17",
  "fraud": false, "duplicate_read": false, "at": "…"
}
```

- 기념품 지급 등은 **`admitted` 일 때만**(재입장 `reentry_ok` 제외).
- `fraud: true` 사유: `forged_qr`, `blocked_ticket`, `sanctioned_account`, `qr_replay`, `duplicate_ticket`.
- `duplicate_read: true` 는 같은 단말이 5초 안에 같은 QR 을 다시 읽은 것 — 새 입장이 아니다.

### 2-5. 회전 QR

`PKT:{티켓번호}:{30초 창 번호}:{HMAC_SHA256(QR_SECRET, "티켓번호:창")[:16]}` — 단말은 **원본 그대로** 보낸다(해석·검증은 서버). 허용 창 기본 ±5(약 ±150초).

## 3. 결제 연동 — 피켓 결제(나이스페이)

| 항목 | 규격 |
|---|---|
| 상점 | 주식회사 노드엑스 가맹 운영 상점(MID). 상점키는 서버 환경 변수에만 두고 결제창에는 상점 아이디만 내려간다 |
| 결제 준비 | 서버가 주문 금액·EdiDate·상점키로 SignData(SHA-256)를 만들어 결제창 값과 함께 내려준다 |
| 결제창 | 나이스 구형 결제창 `nicepay-pgweb.js` 의 `goPay`. 카드사 인증 창(앱카드 QR 등)은 결제창이 띄운다 |
| 인증 결과 수신 | 결제창이 인증 결과를 서버 `POST /api/v1/payments/nice/return`(EUC-KR form)으로 보낸다 |
| 승인 | 서버가 응답 서명·상점·금액·주문 4가지를 대조한 뒤 인증 결과의 승인 주소(NextAppURL)로 승인 요청. 승인 뒤 주문 확정·입장권 활성 |
| 취소 | 서버가 `cancel_process.jsp`로 취소(전액은 PartialCancelCode=0). 팬 「환불 신청」과 관리자 환불이 같은 경로를 쓴다 |
| 상태 확인(Pull) | 거래조회 `trans_status.jsp`로 대사·웹훅 재검증 |
| 브라우저 조건 | 창 격리 정책 `same-origin-allow-popups`, 보안 정책 `form-action`에 API 서버 주소, 결제창 레이어가 앱 화면 위 |
| 기록 | 결제 시도·거부 사유는 원장에 남기고 카드·키는 가린다 |

## 4. 결제 연동 — 주최사 PG 직결

| 항목 | 규격 |
|---|---|
| 상점 키 | 토스페이먼츠 **API 개별 연동 키**(`test_ck_/test_sk_`, `live_ck_/live_sk_`). 결제위젯 키(gck/gsk)는 직결에 쓰지 않음 |
| 등록 | 주최사 대시보드 「정산 방식」 → 상점 키 등록 → 키 확인(토스 조회 API: `404 NOT_FOUND_PAYMENT` = 성공) |
| 연결 | 키 확인 통과 상점만 이벤트에 연결 가능. 정산 방식 `direct` |
| 결제창 | 토스 표준 결제창, 주최사 클라이언트 키 |
| 승인 | 서버가 주최사 시크릿 키로 `POST /v1/payments/confirm` |
| 상태 확인(Pull) | `GET /v1/payments/orders/{orderId}` — 웹훅 미수신 대비, 주최사 화면·대사에서 호출 |
| 취소 | `POST /v1/payments/{paymentKey}/cancel` (주최사 키) |
| 정산 | 대금은 주최사 상점으로 직접 입금(피켓 미경유). 피켓 수수료는 `platform_fee_invoices` 로 별도 청구(기본 5%, 이벤트별 설정) |
| 기록 | 모든 호출은 연동 원장(append-only 해시 체인)에 마스킹 저장 |

## 5. 테스트 기준(합격 조건)

1. 피켓 결제: 운영 상점으로 결제창 → 카드사 인증 → 승인 → 주문 확정·입장권 → 환불 신청 → 나이스 취소 성공 → 주문 「환불」·입장권 「취소」. (2026. 11. 24. 1,000원으로 통과)
2. 주최사 PG 직결: 테스트 키로 결제창 → 승인 → 주문 확정 → 수수료 청구서 → Pull 조회 일치 → 취소 → 청구서 무효.
3. 단말: 사유별 판정 코드가 2-4 표대로 나온다. 차단·제재 변경 후 5초 안에 모든 접속 단말에 `blocklist.sync`.
4. 원장: 연동 원장 해시 체인 재계산 일치, UPDATE/DELETE 거부.
